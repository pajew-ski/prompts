title: Pre-Mortem
level: Intermediate
tags: risk planning
description: Assume the project has failed, name the most likely causes, and find early warning signs for each.
---

The pre-mortem goes back to Gary Klein (2007). Instead of asking after a failure what went wrong, you imagine before the start that the project has already failed and explain in hindsight why. "Why did it fail?" draws different answers than "What could go wrong?": risks become more concrete, and objections that would otherwise sound pessimistic become the assigned task.

## Example

```prompt
Project: [description, goal, timeline, team, budget]

It is one year later. The project has failed.
1. Name the three most likely causes, each with a short explanation of how it came about. Refer to the weaknesses in the description above, not to generic project risks.
2. For each cause, name an early warning sign we can watch for now or in the coming weeks.
3. For each cause, suggest one measure we can take today.
```

## When it helps

Before launching a project, a product or a major decision, while things can still be changed. The more precise the project description, the more specific the causes; without details the model returns textbook risks. The early warning signs turn the exercise into something you can actually check as the project runs.
